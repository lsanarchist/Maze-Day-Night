# День / ніч · технічні нотатки 1.1.0

## 1. Поділ відповідальності

`day-night.js` — незалежний від DOM / Three.js модуль: WorldClock, часові фази, параметрична орбіта та коефіцієнти освітлення. Session у `core.js` володіє одним WorldClock і викликає `advanceStep()` лише з успішного `move()` або `advanceWalk()`. Розрахунок маршруту не торкається годинника. Такий підхід однаково охоплює клавіатуру, екранні кнопки, автопроходження й одиночний крок.

`environment.js` — окрема сцена-група DayNightEnvironment: HemisphereLight, сонячне та місячне DirectionalLight, градієнтне небо, сонячний диск / сяйво, місячна сфера з процедурною текстурою та Points із зорями. ThreeView створює PointLight для гравця та фінішу. Усі текстури процедурні; зовнішніх зображень немає. Ці ресурси звільняються при dispose.

`app.js` — годинник у UI, перемикач тривалості, ручне встановлення часу, JSON і оновлення візуального часу. CanvasView отримує той самий WorldClock, але лише спрощено імітує палітру / тіні / ліхтар у резервному 2D. Жодної підміни цього режиму під WebGL немає.

## 2. Дискретний та візуальний час

Сумарний час `totalMinutes` не обнуляється опівночі:

```text
timeOfDay = totalMinutes mod 1440
day       = floor(totalMinutes / 1440) + 1
```

Початок — 480 хвилин (08:00). У випадковому режимі один перехід додає `30 + floor(random() * 31)` хвилин: усі цілі значення 30…60 включно. Фіксовані режими: 30, 45, 60. Випадковий приріст часу не відтворюється seed карти; для повторюваних демонстрацій слід використовувати фіксований режим. У тестах random ін’єктується.

Годинник у UI показує точний результат кроку одразу. Візуальний час наближається до нього експоненційно:

```text
visual += (total - visual) * (1 - exp(-9 * dt))
```

Інтерполяція виконується над абсолютними хвилинами, не HH:mm. Тому 23:45 → 00:30 рухає світила вперед через північ, а не назад через весь день. Реальний час кадру не збільшує totalMinutes. Для prefers-reduced-motion освітлення перемикається без цієї анімації.

## 3. Умовна орбіта

```text
hour     = timeOfDay / 60
a        = 2π * (hour - 6) / 24
sunDir   = (cos(a), 0.8*sin(a), -0.6*sin(a))
moonDir  = -sunDir
```

Це одиничні протилежні вектори. Коефіцієнти 0.8 / 0.6 нахиляють орбіту над задньою частиною лабіринту й залишають напрямлені тіні читабельними. Модель навмисно художня: світанок близько 06:00, захід близько 18:00; немає географії, сезонів або справжніх місячних фаз.

Ті самі вектори визначають позиції сфер і джерел світла. У 2D сфери приховані, щоб не перекривати карту; підсвічування й годинник зберігаються. Положення світила на екрані 3D залежить від обертання / масштабу камери — його можна вивести за межі кадру. Діаграма над сценою залишається видимою незалежно від камери.

`skyStateAt` використовує гладкі переходи для daylight, twilight, night і потужності джерел. Уночі сонячне джерело відключене, місячне активне; локальний ліхтар має теплий колір і рухається разом із гравцем. Зорі проявляються плавно. Світло під горизонтом не освітлює дошку знизу.

## 4. Правила стану

| Дія | Світовий час |
|---|---|
| Успішний ручний перехід | +30…60 або фіксований приріст |
| Один перехід автопроходження / N у режимі руху | Такий самий приріст |
| Удар у стіну, відхилений busy-ввід | Без зміни |
| Крок BFS / DFS / A* | Без зміни |
| Очікування, камера, редактор, undo / redo | Без зміни |
| R / повернення гравця на старт | Без зміни |
| Новий лабіринт | День 1, 08:00; налаштування кроку / ліхтаря збережені |
| Меню встановлення часу | Автоматична задача ставиться на паузу; явне переведення годинника |
| Окрема кнопка скидання годинника | День 1, 08:00, без зміни позиції гравця |

## 5. Збереження

Формат карти версії 1 збережений. Експорт UI додає необов’язковий об’єкт:

```json
"world": {
  "version": 1,
  "totalMinutes": 1470,
  "stepMode": "45",
  "lantern": true
}
```

Експорт також може містити похідні day / time / phase / lastStep для читання людиною. Відновлення спирається тільки на валідовані totalMinutes, stepMode та lantern. totalMinutes — ціле 0…1 000 000 000, режим — random / 30 / 45 / 60, lantern — boolean. Неправильний world відхиляє імпорт до будь-якої зміни поточної карти. Файли без world відкриваються з початковим часом. Позиція гравця не входить до збереження, як і раніше.

## 6. Перевірки та межі підтвердження

63 нових Node.js-тести перевіряють прирости, межі випадкового діапазону, північ, кілька днів, інтерполяцію, стани гри, формат збереження та властивості орбіти. Браузерний сценарій додає 31 перевірку реального DOM / контролера / Canvas. Разом із попередньою функціональністю — 145 тестів Node і 63 браузерні перевірки.

У середовищі підготовки не було доступу до завантаження npm/CDN-бібліотеки, тому реальний WebGL, GPU-тіні, шейдер неба та офлайн-вбудовування Three.js не перевірені запуском. `tests/day-night-browser.py --url ...` після локального встановлення залежності вимагає саме Three.js і перевіряє активні світла, зорі, обидві камери та PNG сцен. Поки цей сценарій не пройдено з WebGL, прикладені Canvas-скріншоти не слід вважати 3D-валідацією.
