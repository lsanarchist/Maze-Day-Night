# Maze Lab · Three.js · 1.1.0

Інтерактивний генератор лабіринтів із **перемиканням камер 2D / 3D**, ручним проходженням, покроковою візуалізацією BFS / A* / DFS і редактором карти.


## Нове: день, ніч і час за кроками

Над сценою розташований годинник із номером дня, поточною порою доби та схемою руху сонця й місяця.
Початок нової карти — **день 1, 08:00**. За замовчуванням кожен успішний перехід гравця додає випадкове ціле число **30–60 хвилин включно**. Поруч можна обрати фіксовані **30 / 45 / 60 хвилин**. Наприклад, при 45 хв/крок: 08:00 → 08:45 → 09:30. Після 23:59 починається наступний день.

У Three.js додані рухомі сонце й місяць, напрямлене денне / місячне світло з тінями, градієнтне небо, зорі та теплий ліхтар гравця. Сонце й місяць показуються у 3D; у 2D вони не перекривають карту, але час і світло ті самі. Числовий годинник одразу показує результат кроку, а освітлення та небесні тіла плавно переходять до нього. Ніч лишається придатною для проходження.

Час **не витрачається** на пошук BFS/A*/DFS, удар у стіну, очікування або перемикання камери. Автопроходження і покрокове проходження витрачають час так само, як ручний рух. `R` повертає гравця на старт, але не переводить світовий годинник назад. Редагування й undo/redo також зберігають час; генерація нової карти скидає його.

Меню **«Час»** містить світанок / полудень / захід / ніч, повзунок, точне поле ГГ:ХХ і окреме скидання годинника. Відкриття меню ставить пошук / автопроходження на паузу. Кнопка ліхтаря вмикає чи вимикає локальне нічне підсвічування. JSON зберігає карту **та час, режим кроку й налаштування ліхтаря**; старі карти без блоку `world` теж підтримуються.

Це стилізований 24-годинний цикл, не астрономічний розрахунок для реального місця й дати. Деталі: `docs/DAY_NIGHT.md`.

## Запуск

### Найпростіше: один HTML

Відкрий **`dist/index.html`** у браузері. У наданій збірці Three.js завантажується з CDN, тому **для 3D потрібен інтернет**. Власний код, стилі та іконки вже всередині HTML. Якщо Three.js або WebGL недоступні, застосунок явно показує резервний Canvas 2D і вимикає кнопку 3D; він не видає резервний режим за 3D.

Файл треба відкрити у браузері після збереження на комп’ютер, а не переглядати як текст у вікні попереднього перегляду файлу.

### Локальний проєкт: рекомендовано для розробки

Потрібен Node.js 18 або новіший. У папці з `package.json` виконай:

```bash
npm install
npm start
```

Відкрий адресу, надруковану сервером:

```text
http://localhost:5173
```

`npm install` один раз завантажує зафіксовану залежність **`three@0.180.0`**. Сервер автоматично використовує встановлену локальну бібліотеку. Після цього інтернет для роботи застосунку не потрібен. Без `npm install` сервер теж запускається, але використовує CDN.

На Windows можна запускати `START-WINDOWS.bat`; на Linux/macOS — `./START-UNIX.sh`. Ці файли запускають сервер, але самостійно не встановлюють залежності. Сервер прив’язаний лише до `127.0.0.1`; це локальний інструмент, а не production-сервер.

### Повністю автономний HTML з усією Three.js усередині

```bash
npm install
npm run build
```

Коли залежність встановлена, збирач вбудовує офіційні модулі Three.js і OrbitControls у `dist/index.html` як data URL. Цей HTML можна перенести на інший комп’ютер і відкрити без мережі та без Node.js. Браузер і GPU все одно повинні підтримувати потрібний WebGL.

Якщо виконати `npm run build` без встановленої залежності, збирач створить CDN-варіант і прямо повідомить про потребу в інтернеті для 3D. **Наданий тут готовий HTML — саме CDN-варіант.**

| Дві камери | 2D: OrthographicCamera зверху. 3D: PerspectiveCamera, OrbitControls, об’ємні стіни, освітлення, тіні. Перемикання не змінює карту, гравця чи алгоритм. |
| Пошук | BFS, A* з мангеттенською евристикою, DFS; анімація; пауза; один крок; регулювання швидкості. |
| Автопроходження | Рух гравця знайденим маршрутом; пауза і покрокове продовження. |
| Ручне проходження | WASD / стрілки / екранні кнопки; перевірка стін; лічильник кроків; фіксація фінішу. |
| Редактор | Додавання/видалення стін, переміщення старту і фінішу, undo/redo на 50 змін. Працює в обох видах; зверху редагувати найзручніше. |
| Файли | Експорт та імпорт JSON із перевіркою структури; знімок сцени PNG. |
| Інтерфейс | Українська мова, мінікарта в 3D, легенда, статистика, довідка, About, адаптивне компонування. |
| Резервний режим | Canvas 2D без зовнішньої бібліотеки; чесно позначається і не дозволяє перемкнутися в 3D. |

## Керування

| Дія | Клавіша / жест |
|---|---|
| Рух по карті | `W` / `↑` — північ; `D` / `→` — схід; `S` / `↓` — південь; `A` / `←` — захід. |
| Камера 2D / 3D | Кнопки зверху або `V`. |
| Обертання в 3D | Перетягування лівою кнопкою миші в режимі проходження. |
| Зсув карти | Права кнопка + перетягування; у 2D також ліва кнопка в режимі проходження. |
| Масштаб | Колесо миші; у Three.js також двопальцевий жест. |
| Умістити карту | `F` або кнопка з рамкою. |
| Пошук / пауза / продовження | `Space`, коли фокус не в текстовому полі або кнопці. |
| Один крок | `N` або кнопка біля запуску. |
| Повернути гравця на старт | `R`. |
| Undo / redo у редакторі | `Ctrl+Z`; `Ctrl+Shift+Z` або `Ctrl+Y`; на macOS також `Cmd`. |

**У 3D WASD прив’язані до сторін карти, а не до поточного повороту камери.** Мінікарта завжди орієнтована північчю вгору. Це оглядова 3D-камера, не режим від першої особи.

Під час активного пошуку чи автопроходження ручний рух заблокований. Після паузи ручний рух дозволений, але скасовує попередній пошук, оскільки початкова позиція змінилася. Пошук завжди починається **від поточного положення гравця**.

## Важливі особливості

- При 0% додаткових проходів генератор створює зв’язний лабіринт-дерево. З додатковими проходами з’являються альтернативні маршрути, тож відмінності BFS / A* / DFS помітніші.
- Для відтворення карти потрібні однакові seed, ширина, висота, відсоток проходів і версія генератора. Seed не відтворює ручні зміни — їх зберігає JSON.
- «Швидкість пошуку» задає бажані розширення вершин за секунду; реальний темп залежить від частоти кадрів. Автопроходження йде окремо зі швидкістю близько 6 переходів/с.
- Стіни зберігаються з обох боків межі. Зовнішня межа завжди закрита. Старт і фініш — внутрішні позначені клітинки, а не отвори в зовнішній огорожі.
- Редагування скидає результати пошуку та повертає гравця на актуальний старт. Зміна тільки камери нічого з цього не робить.
- Редактор може створити нерозв’язну карту. Пошук у такому разі закінчується повідомленням «Шлях не існує».
- Після відходу на іншу вкладку активна симуляція автоматично ставиться на паузу.
- Немає автоматичного збереження між перезапусками. Збережи JSON перед закриттям; при незбережених ручних змінах застосунок запитує підтвердження заміни карти та попереджає про закриття вкладки.
- PNG містить лише сцену. JSON зберігає карту та блок світового часу `world`, але не позицію гравця, камеру, історію undo чи поточний крок алгоритму.

## Приклади карт

`examples/open-4x4.json` — відкритий простір: від старту до фінішу найкоротший шлях становить 6 переходів.

## Перевірки

```bash
npm test
npm run check
```

Тести ядра не потребують Three.js і працюють навіть без `npm install`.

Для браузерних перевірок, за наявності Python:

```bash
pip install playwright
playwright install chromium
python tests/browser_smoke.py
```

За замовчуванням цей сценарій **навмисно блокує мережеві запити**, завантажує реальний HTML в ізольовану сторінку й перевіряє інтерфейс, контролер та резервний Canvas 2D. Це не тест WebGL.

Для перевірки встановленої локальної Three.js, у двох терміналах:

```bash
# Термінал 1
npm install
npm start
```

```bash
# Термінал 2
python tests/browser_smoke.py --url http://localhost:5173
```

Для власного Chromium можна додати `--browser /path/to/chromium`.

Результат підготовки цієї версії: **145/145 тестів логіки (82 попередні + 63 нові), 63/63 браузерні перевірки резервного режиму (32 регресійні + 31 нова), синтаксичні перевірки пройдено.** Реальний WebGL-рендер, завантаження CDN і повністю автономну збірку з офіційними модулями Three.js у середовищі підготовки перевірити не вдалося через мережеві обмеження. Деталі — `docs/TEST_REPORT.md`.

## Перед використанням як семестрового проєкту

Заповни власні дані в **`src/config.js`**. Ім’я автора навмисно залишене шаблоном. Після зміни конфігурації або коду виконай `npm run build`, щоб оновити single-file HTML.

Описані функції реалізовані в коді, але це не гарантія погодження конкретного обсягу викладачем. `docs/USER_GUIDE.md` і `docs/SYSTEM_GUIDE.md` — матеріали для документації, а не вже оформлені за методичкою окремі PDF/DOCX з нумерацією сторінок та титульними аркушами.

## Залежності й джерела

Офіційна Three.js: `https://threejs.org/`.

Ортографічна камера: `https://threejs.org/docs/pages/OrthographicCamera.html`.

Перспективна камера: `https://threejs.org/docs/pages/PerspectiveCamera.html`.

OrbitControls: `https://threejs.org/docs/pages/OrbitControls.html`.

Використана залежність: `three@0.180.0`, ліцензія MIT. Оригінальна ліцензія постачається з npm-пакетом. CDN-запити до стороннього постачальника відбуваються тільки для бібліотеки; карти застосунок не відправляє. Для повністю локальної роботи встанови залежність і користуйся локальним сервером або автономною збіркою.

### Додаткова перевірка дня / ночі

```bash
python tests/day-night-browser.py --browser /path/to/chromium
# Після npm install і npm start, у другому терміналі:
python tests/day-night-browser.py --url http://localhost:5173 --browser /path/to/chromium
```

У режимі `--url` новий тест вимагає справжній Three.js/WebGL і завершується помилкою, якщо завантажився лише fallback. Скріншоти в `docs/previews/` зняті саме у резервному Canvas 2D й не є підтвердженням WebGL-рендера.
